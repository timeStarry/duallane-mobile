# Android 1.1.0：助手能力与更新门槛

## 用户行为

- 手机独立配置助手发现、私聊、群内使用和来源 Bot，明确保存 V2 权限；读取旧策略不自动转换。
- 创建者发起入群请求，群管理员批准或拒绝；批准入群不自动开放私聊或历史读取。
- 接入指引要求官方清单、摘要、Skill 和明确可信的命令桥接，不替换已有凭据和策略。
- 读取服务端卡片引用，显示受限 Feishu 正文与固定按钮；动作使用空输入、预期版本和稳定操作编号。
- 返回会话先显示底部，保留新消息回看入口；输入框上方显示思考状态；提及保留真实成员 ID 并支持键盘跟随。

## 双版本与两个门槛

APK 使用真实 `nativeVersion/versionCode` 判断更新，OTA 使用界面版本和 bundle ID。
`minimumSupportedNativeVersionCode` 控制是否允许继续使用；OTA `minNativeVersionCode`
仅控制该资源包的原生兼容下限。未知原生版本不能伪装成当前新版本。

本版 APK 的语义版本为 1.1.0，默认 versionCode 为 10100；以最终签名产物元数据为准。
兼容 OTA 保留最低 10051，以便旧 1.0.10～1.0.12 壳先获得更新提示。
最低可用原生版本在正式激活前选择：10054 可保留 1.0.13 及以上壳的迁移兼容；
10100 是本版首次原生版本声明基线，启用它会要求所有旧壳安装一次新 APK。
门槛默认停用，必须在新签名 APK 和兼容 OTA 均核验可下载后显式启用。

强更页允许下载、校验、重新检查、退出和系统安装确认，不提供跳过继续使用。
断网保留已获知的门槛，不能因一次失败自动解除；服务端公开策略支持明确撤回门槛。
草稿和在途写入阻止自动热更重载；热更失败保持原生预置回退能力。

## 已知兼容边界

旧壳能通过兼容 OTA 为 HTTP 附加真实原生版本，但旧 Kotlin 后台 WebSocket 会丢弃
JS 声明，只能由新 APK 补齐。服务端对已声明旧版本的业务请求拒绝，未声明的旧后台
连接在最低要求低于 10100 时保留迁移兼容；达到 10100 后，已认证移动 Bearer 业务
HTTP/WS 必须声明原生版本，缺失即拒绝。Cookie Web 会话和下载恢复保持独立。
版本声明是兼容元数据，不能代替身份、会话、配额或对象授权。
这不是对恶意伪造版本的设备认证，也不宣称旧壳已获得新的 Kotlin 行为。

## 发布与验证

1. 两仓均走 PR、完整 CI 和对应 Go/PG、浏览器回归。
2. 验证签名 APK/AAB、实际 versionCode、同签名身份和摘要；发布前保留为 draft。
3. 用旧壳及当前壳验收卡片、权限、草稿、上传、冷启动、前后台恢复和强更安装流程。
4. 服务端先发布兼容能力（门槛为 0）；核验 APK 与 OTA 后再显式启用最低版本。
5. 核验公网清单、APK/OTA 摘要和强更/回退路径。不得把仅后端创建成功当作卡片界面验收。

只使用合成数据验收，不重放已有 Comet 任务或操作。P2P 不改变服务器不持久化承诺。
本文件描述目标和验收要求；最终完成项、未执行项和正式产物记录在 PR 中。
