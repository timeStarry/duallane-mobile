# R4：Workspace 聊天补全与 Android 实测记录

日期：2026-09-26。实现分支：`codex/complete-workspace-chat-android`，叠加在 `feat/android-i0-i3` 上。此文记录实际运行结果；[完整验收账本](ACCEPTANCE.md) 的未运行条目不会因代码或单测通过而自动改为通过。

## 本轮可观察行为

- 群详情显示常驻消息、话题和会话文件；常驻消息可回到原消息。私聊详情也显示其会话文件，文件预览保留服务端下载能力标记。
- Markdown 用原生组件显示标题、引用、列表、围栏代码、行内强调、安全 HTTP 链接和 catalog 表情；HTML、表格及未知协议保持纯文或安全降级。
- 已注册 Echo 征集卡可选项并投票，需求卡可按服务端允许动作更新状态；未知类型、版本和动作不继承入口。
- 表情合集从消息卡片取得授权详情，支持预览、整套导入与可用时订阅源更新；可下载的消息图片可收藏为个人表情。原消息摘要不作为访问凭据。
- 登出或切换账号时清除个人表情资源映射，避免旧账号的媒体引用留在新会话。
- `@` 候选不再收起键盘；消息正文、链接、附件和显式操作按钮各自接收触控；动作面板可滚动并避开安全区，媒体查看器有独立关闭入口。
- 话题附件以 `private_staging` 预留；丢失或中断的上传任务不会把原附件消息误发成纯文本。失败重试保留目标、附件任务和同步到群的选择。实时消息的会话未读取服务端投影，话题事件刷新话题投影。

发现并在后续提交修复：原 `下载并保存` 实际只打开分享选择器、分享文件名带随机前缀；快捷反应发送无效的裸 emoji 且失败无提示；“关于与更新”显示 `0.1.0`，与已安装的 `0.2.0 / code 2` 不符。修复包需重新在真机检查保存、分享、反应和实际版本显示；本节不把代码修复当成真机通过。

`0.2.1` / versionCode `3` 修复包在 [Android CI 运行 36210258283](https://github.com/timeStarry/duallane-mobile/actions/runs/36210258283) 完成 debug／测试签名 release APK 与 AAB、签名和 manifest 校验，以及 Android 15 模拟器浅色／深色冷启动与重启 smoke。APK SHA-256 为 `d9f7c82b2784921e70f8a3df613839fe12cfc7a1f525c9e3059fd8932334ad9e`，大小 76,491,717 字节，测试证书 SHA-256 为 `11e15cd432fd0c06341ef43cbf84eec36d887263a05a53edb7460fbf02f3ae74`；构建时默认服务仍注入 `https://duallane.tsio.top`。这份包已经在同一 Redmi 测试机卸载旧测试签名包后安装、冷启动到登录页。安装时服务端正切流，更新检查和 GitHub 登录请求出现 `net.tls`，在线回归暂停；此现象不归因于客户端修复，也不能据此宣称登录后的功能通过。

当前真机稳定显示“实时未接通，已用 HTTP 同步”，HTTP 消息、附件与话题调用可用。尚未确定原因是移动端 WebSocket、设备代理／网络路径还是公网入口；因此不能声称实时收发、后台通知或断线恢复通过。完整 Web↔Android 双向、受限文件、弱网上传、长历史、辅助技术、窄屏与高字体等仍按 [验收账本](ACCEPTANCE.md) 逐项验证；未运行条目不由 CI 启动 smoke 代填。

## 仍需独立处理的范围

原生 Markdown 不解析表格、远程 Markdown 图片或嵌套任务列表；这类输入保留可读的纯文回退。自定义表情合集创建／分享／排序、空间管理、P2P、后台远程推送和 OTA 服务不属于本轮 Android 聊天交付。测试签名 APK 与既有不同签名不能覆盖安装；正式发布需维护者配置稳定的 Android 签名密钥。
