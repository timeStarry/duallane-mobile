## 2. 用户在手机上如何完成任务

窄屏默认一条路径：**根 Tab → 单一对象页 → 按需详情**。四个根目的地仍是聊天、文件、成员、我的。聊天首页用「会话／话题」分段承接 Web 的两个日常入口，不增加第五个底部 Tab。

1. 冷启动无会话：GitHub 登录。发布包不选服务器。邀请默认在「还没有账号？」后展开。
2. 登录成功：聊天列表。点一行进入该会话；根 Tab 隐藏，标题是对象名，详情是头部动作。
3. Android 返回：先关键盘／浮层，再回上一层。返回列表不是退出账号。
4. 文件、成员从根 Tab 进入；与聊天附件共用文件行语义，但不把文件库上传伪装成当前会话发送。
5. 「我的」是分类目录。本机外观立刻生效；通知权限与会话提醒分开；退出在独立危险区。

话题、回复、表情、卡片和附件预览后发送属于 R2。R1 已把入口、层次、正式组件和当前可接线的个人设置放到正确位置，不为未接线的能力提供可点即“成功”的按钮。

## 3. 进入 R1 的条件

- 设计说明已经按任务写清手机动线，见 [MOBILE_FLOWS.md](MOBILE_FLOWS.md)。
- 原色浅／深 token 有可追踪映射，页面不再散落品牌十六进制值。
- 开发构建可打开工作台，工作台 import 正式组件而非截图副本。
- 根目的地、登录、列表、详情和设置目录使用同一套 primitives。

R1 代码已满足上述进入条件。R2 代码已接线 MSG-01–MSG-12。不得宣称完成的事项：双向跨端验收、真机／TalkBack 证据、签名发布包体验评审。
