# DL Android 改造验收账本

对应 [改造要求](README.md)。本表 **判定** 是真机／跨端／签名包验收，不是单测。
当前判定仍为 **未运行**（OTA 为不适用）。自动化覆盖和本机命令输出记在 [R3 证据](R3.md)。
下一轮 IME 方程、动作簇、分组气泡见 [体验全面迭代](../android-experience-iteration/README.md)，真机/TalkBack 仍未跑。
写下用例、有代码或有 Jest 通过，都不能把本表改成通过。现有 APK 的联通性验证不得代填本账本。

## 1. 测试对象与证据

默认在隔离环境使用两个合成普通成员 A、B，一个可授权测试管理员、一个 Bot、至少两个群 G1/G2、一个可加入话题 T1 和关闭话题 T2。准备普通消息、长中文、@、emoji、自定义表情、图片、文件、已知／未知卡片、回复、撤回和隐藏状态。管理员只用于准备／撤权；不借验收给移动端加入管理页面。

真实生产账号必须有明确授权会话；不发送测试内容到其他会话，不把真实头像、消息、文件名、成员关系或 token 写入公共截图、日志与仓库。

每一项实施后填入以下信息，不能只写一个“通过”：

| 字段 | 必填内容 |
| --- | --- |
| 版本 | 移动 commit、主仓 commit、运行服务端版本、APK versionCode／SHA-256 |
| 环境 | 设备型号、Android API、逻辑尺寸 dp／截图像素、fontScale、浅深主题、导航方式、网络路径 |
| 实施 | 对应代码／PR、适用的会话类型、未实现／阻塞项及原因 |
| 验证 | 步骤、实际结果、执行日期、自动化报告或合成内容截图／录像链接 |
| 判定 | 通过／失败／未运行／不适用；不适用必须有领域范围依据，不能用来隐藏实现缺口 |

## 4. 检查方式与发布门槛

R3 在开发机执行下列命令，并把摘要写入 [R3 证据](R3.md)。真机、模拟器安装、双向跨端和正式签名包仍按未运行处理：

```text
corepack pnpm install --frozen-lockfile
corepack pnpm check
node --test plugins/*.test.cjs
corepack pnpm export:android
git diff --check
```

构建／签名／安装命令与更新场景遵循 [测试与发布规范](../../development/TESTING_AND_RELEASE.md)。UI 组件和状态回归使用 RN 测试；Android 页面／IME／系统选择器／返回／通知用原生自动化与人工实测；Web 对照使用真实 Web 客户端。Playwright Web 成功不能代替 Android 行为验收。

必须有至少一台真机的主流程／中文输入／系统返回／后台恢复／TalkBack 证据；模拟器另覆盖尺寸、系统版本和自动化失败路径。API 26 最低支持版本与当前构建 targetSdk 对应版本都要安装／启动／关键导航验证。必要的服务端变更另跑主仓受影响契约与集成检查，不能让客户端 mock 证明权限和配额正确。

以下问题阻断“DL 改造完成”的交付：

- 核心已知消息只能 fallback、回复／话题关系丢失、同名动作在两端后果不同。
- 草稿丢失、错目标发送、重复消息、错误已读、权限／配额／账号隔离退化。
- 任一主要页面仍是另一套视觉或组件，手机键盘／安全区／返回导致主任务不可完成。
- 关键步骤只有截图或 mock，实际 APK、双向跨端、真机／辅助技术未验证却标为通过。
- 发布包需要用户重新选择默认服务，或只能清数据／卸载后运行而未说明签名及升级兼容性。

OTA 当前未配置时保持禁用，记录“不适用”，不能声称 OTA 验收通过；若改造引入新原生模块或运行时，走新 APK 与对应版本。设备会话管理、更多主题家族、跨设备草稿、远程推送、全文搜索等独立范围不靠占位 UI 交差，也不在本表中冒充本轮已交付。

最终发布记录同时附本次范围、已完成项、真实未覆盖项、APK hash 与当前证据。体验验收和后端健康检查分别报告，不再以连通性 smoke 代替完整产品验收。
