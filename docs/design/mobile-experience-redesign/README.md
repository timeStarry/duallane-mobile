# DL Android 体验改造要求

状态：要求已冻结；R0／R1／R2 已实现，R3 证据账本已建立。2026-09-17 根据当前 APK 的体验反馈制定。验收账本的判定栏仍为未运行；自动化与未覆盖项见 [R3 证据](R3.md)。本文件不是「DL 体验改造完成」。

目标：让用户在 Web 与 Android 上理解同一套 DL 对象、动作和结果，同时在手机上使用自然、顺手的布局与交互。跨端一致不等于页面、像素、控件位置或操作手势完全相同。

- [已有联通性验证](https://github.com/timeStarry/duallane-mobile/releases/download/internal-0.1.0-20260916/android-15-production-verification.json)只证明真实账号登录、基础消息、文件、登录恢复和重连等所列场景。它不是 UI、美术、完整聊天或跨端体验验收。

### 1.2 必须保持的边界

- 仅 Android、仅共享空间。私聊仍是服务端留存的共享空间会话；不加入 P2P、通道选择、多空间切换或 iOS。
- 不加入空间管理后台：邀请管理、角色与成员可见性、空间容量和保留策略、操作记录、Bot 凭证及管理继续由 Web 承担。个人偏好、会话提醒、允许的聊天动作不应因此被一起删掉。
- 发布包默认服务仍为 `https://duallane.tsio.top`，构建注入；首次使用无需选择或填写服务地址。测试网关不是产品配置或用户步骤。
- 保持 PKCE／Custom Tabs、Keystore、消息 canonical 对账、权限与配额、账户隔离、低版本安全 fallback。新 UI 不重新实现认证或放宽后端授权。
- 通知仍为 WebSocket 驱动的 Android 本地通知；普通后台可延迟，不承诺进程结束后的即时推送，不增加保活、FCM 或改变 ntfy。
- 本轮不承诺跨设备草稿同步、全文历史检索、通用消息编辑、通话等尚无完整当前契约的能力；不得用装饰性按钮暗示已支持。

## 2. 跨端一致与移动适配

| 必须一致的语义 | Android 的自然表达 | 验收重点 |
| --- | --- | --- |
| 同一账号、成员、群、话题、文件与消息身份 | 单窗格返回栈、清楚的标题和所属群；不压缩桌面三栏 | 从两端打开同一对象，名称、归属、权限和内容一致 |
| 查找、阅读、发送、回复及对象动作的含义 | 常用动作就近；长按动作面板，同时保留可发现的“更多”入口 | 用户换设备后无需重新理解动作；关键功能不只藏在手势里 |
| 未读、提醒、发送／上传失败、撤回与隐藏的结果 | 小型状态标识、行内反馈、Android 系统通知 | 同名状态含义相同，不能把“已发送”表示成“对方已读” |
| DL 的品牌、层次、内容密度、主题语义 | RN token、系统字体、触控命中区、原生安全区 | 看得出同属 DL；可读性、触控与平台行为优先于像素复刻 |
| 草稿、阅读位置和当前对象的作用域 | 按账号＋空间＋会话／话题保存本机状态 | 返回、切 Tab、打开文件或切主题不丢状态；不承诺跨设备同步 |
| 相同业务权限与错误结果 | 就近解释、可恢复的重试、失权后安全返回 | 隐藏按钮不取代服务端授权，错误不泄露资源是否存在 |
| 文件对象与授权／额度语义 | Android 文件选择、预览、另存和系统分享 | 相同文件内容、所属对象及可见性；不得使用私有存储 URL 绕过授权 |
| 设置的对象与保存含义 | 分类列表→独立设置页；短枚举分段控件、长选项选择面板 | 本地偏好与服务端偏好明确区分，不产生同名相反设置 |

不要求复制桌面侧栏宽度、悬停工具条、右键位置、Web CSS 或所有设置目录。复制对象关系、操作语义、已支持内容和状态，重新设计手机的入口及动线。

## 3. 当前缺口与改造方向

下面是实现起点，不是完整产品验收。源码引用均位于本次移动端基线；实现时应把每项映射到新组件与验收证据。

| 当前事实 | 影响 | 本轮要求 |
| --- | --- | --- |
| `src/ui/theme.tsx` 只有独立的浅深配色对象；`src/ui/components.tsx` 以通用文字按钮、输入框和 Notice 为主 | 仅颜色相近无法形成 DL 的组件层次、动作等级与状态语言 | 建立语义 token → 组件 token → RN primitives 的明确映射 |
| `App.tsx` 的 Chat 原生标题固定“聊天”；页面内另承载会话内容标题 | 会话身份、返回和详情动作未组成统一头部 | 一个主标题区放当前对象与必要上下文；避免两层重复导航 |
| 主要业务页面集中在 `src/features/screens.tsx` | 现有骨架未形成可评审、复用的聊天与设置组件体系 | 按功能拆分，并交付使用同一正式组件的开发工作台 |
| [`MessageRow`](https://github.com/timeStarry/duallane-mobile/blob/b53bc219d7ed2c473561ead301886c2498855fbf/src/features/screens.tsx#L33) 只使用 `plainText`；[消息解析](https://github.com/timeStarry/duallane-mobile/blob/b53bc219d7ed2c473561ead301886c2498855fbf/src/domain/contracts.ts#L9) 尚未接入卡片、话题引用和表情合集 | 已认识的 mention／emoji 仍被压平，当前已知扩展内容被当成低版本内容 | 保留安全 fallback，补齐正式内容渲染和操作 |
| [`Runtime.send`](https://github.com/timeStarry/duallane-mobile/blob/b53bc219d7ed2c473561ead301886c2498855fbf/src/data/runtime.ts#L114) 只构造 text／attachment，回复目标固定为 null；消息模型未接 reactions／pin／topic | 回复、@、反应、常驻及话题关系无法在手机端完整表达 | 补齐对象字段、命令、事件投影和上下文动作，不只补按钮 |
| [聊天文件选择](https://github.com/timeStarry/duallane-mobile/blob/b53bc219d7ed2c473561ead301886c2498855fbf/src/features/screens.tsx#L39) 直接上传并发附件消息；无文本＋附件组合草稿 | 文件选择和真正发送缺少确认与编辑阶段 | 选取→预览／编辑→明确目标→发送，取消不产生消息 |
| [历史与滚动](https://github.com/timeStarry/duallane-mobile/blob/b53bc219d7ed2c473561ead301886c2498855fbf/src/features/screens.tsx#L35) 已有更早消息按钮、近底部滚动和回到最新 | 不能称为完全没有历史能力；仍缺引用定位、稳定返回锚点与可见已读验收 | 补足完整阅读流程，并保留已有分页与去重 |
| 现有基础链路可登录、发送文本、传文件、重连 | 功能连通仍不足以证明富消息、话题、对象操作和多端状态一致 | 按第 6 节和验收账本逐项补齐，不以纯文本 fallback 代替支持当前已知内容 |

已有浅深主题、状态栏适配、草稿缓存、发送失败重试、clientMessageId 对账、分片传输、下载后分享、`all/mentions/muted` 与本地通知是保留项，不应描述成从零新增。设备会话管理只是原方案的目标，现有页面未提供；不得把方案中的功能清单当成已实现事实。

## 4. 页面布局与手机任务流程

### 4.1 导航与壳层（NAV）

1. 保留四个根目的地：**聊天、文件、成员、我的**。聊天首页提供清楚的“会话／话题”同级切换，承接 Web 的两个日常目的地，避免在窄屏硬塞第五个底部入口。这是移动端布局决策，不改变话题对象或权限。
2. 私聊、群聊、Bot 对话、话题使用同一消息页骨架；话题附加所属群、状态和明确的发送目标。全局话题列表与群详情中的话题入口进入同一对象。
3. 进入聊天或详情后隐藏根底部栏，保留单一返回路径。窄屏为列表→聊天→详情；宽屏／横屏只在空间足够时增加列表并列，禁止挤成三栏。初版宽屏可以保留居中单窗格，不得拉长气泡到整屏。
4. Android 返回先关闭键盘／当前浮层，再返回上一层；从通知、群卡片或搜索定位进入也有合理上级。不可把普通返回等同于退出账号。
5. `conversationId` 与 `topicId` 是不同导航目标；切换发送目标前加载并校验目标权限。不能在话题 A 的页面向群 B 发送，或把群草稿误放到话题输入框。
6. 详情默认关闭；一次只占用一个主要滚动区域。打开图片、设置或系统选择器再回来，应恢复对象、草稿、引用和阅读锚点。

### 4.2 登录与异常入口（ENTRY）

- 使用 DL 图标、简短“共享空间”定位与一个 GitHub 登录主按钮；说明聊天和文件保存到空间，不添加营销 Hero、配置向导或进入空间二次确认。
- 邀请是登录上下文／次要入口，默认显示「还没有账号？」小字，不能抢占已有账号的主路径；仅接受当前服务的邀请。OAuth 取消、超时、未受邀请、空间关闭、会话失效分别提供安全解释和可执行的下一步。
- 登录成功进入聊天列表；版本检查网络失败不能伪装成强制更新。已确认的最低版本门禁必须保留，普通更新不得打断当前编辑任务。

### 4.3 会话与话题列表（LIST）

- 稳定行结构：头像／类型、名称、最近内容摘要、时间、未读／提及／免打扰状态。使用对齐和轻分隔，不把每行做成大圆角卡片。
- 搜索、筛选和“发起私聊”可发现；搜索输入提示必须写明实际范围，不把已加载列表过滤称为“搜索全部聊天记录”。联系人范围由服务端决定。
- 新消息可以更新排序，但不得让触控目标在按下至抬起期间换成另一个对象；返回恢复列表筛选和位置。加载／空态／失败／离线缓存具有同样的主要几何结构。
- 话题行显示标题、所属群、加入／未读／关闭状态。进入未加入话题按授权展示预览和“加入讨论”；失权、已关闭／归档提供准确状态，不能伪装成空消息列表。

### 4.4 聊天与编辑器（CHAT）

- 头部一层：返回、可读会话名／话题名、必要的所属群或连接异常状态、详情／更多；正常连接不常驻占一大块正文空间。
- 中部为虚拟化消息流，区分本人、他人、系统消息；按作者和时间适度合并，显示日期、未读分界和发送状态。正文优先，元信息克制，头像、附件和气泡预留尺寸。视觉分组沿用 DL 的同作者／类型／本人归属、同本地日期且相邻间隔不超过 5 分钟规则；回复、隐藏、撤回、系统及未读分隔打断分组，消息 ID 和单条动作始终独立。
- 底部固定编辑器：附件／表情入口、多行输入、发送；引用条、选中文件和当前话题发送上下文放在输入区内。初始一行，增长至约 5–6 行后内部滚动，随字体尺寸适配，不能把发送按钮挤出可视区。
- 软键盘默认回车换行、显式点击发送；输入法候选词确认不得触发发送。外接键盘快捷键沿用可理解的发送偏好且不影响中文组合输入。
- 附件、表情、@ 候选面板采用底部面板或键盘替换区，二者不重复占满屏幕。收起面板恢复输入焦点；选择失败／取消不清空文本。
- 阅读历史时到达新消息保留锚点，显示“新消息／回到最新”；上拉取历史不跳动。从历史或引用窗口主动提交并成功入队后，立即恢复该目标的最新时间线，附件不等上传完成才滚动；无效提交不移动，迟到回执不得拉走已切换目标的用户。不能用每次数据变化强制滚到底部。
- 有效提交进入本地待发送队列后释放该次输入，允许立即写下一条；旧回执不能清空新草稿。失败项保存原内容、附件、引用和目的地，在别的会话点击重试也不得改投当前会话。
- 长按消息打开按对象能力生成的动作面板；读屏和无法长按的用户仍有动作入口。拖动滚动、文本选择、链接点击与长按必须避免互相误触。

### 4.5 文件、成员与个人（SUPPORT）

- 文件库与聊天附件共用文件行／预览／传输任务状态。独立上传与当前会话上传明确区分；先显示目标和附件预览，用户确认后发送，系统文件选择器取消不产生消息。
- 图片按安全的媒体模型内联呈现，并可打开全屏预览；普通文件展示名称、类型、大小、状态与下载／分享。长名称可查看完整值，损坏／过期／撤回／无权访问有终态。
- 成员列表采用可见联系人范围，提供搜索、轻量资料和发起私聊；不能从全群成员推导空间通讯录或展示本无权查看的成员。
- “我的”是分类入口，不是把身份、主题、提醒和退出按钮堆在一页：个人资料、外观与阅读、聊天偏好、通知、只读空间信息、关于与更新。设备会话属于独立依赖项，确认服务端列表／撤销契约后再开放，不放假入口。只呈现当前已支持且属于个人的设置。
- 设置依据属性自动保存并显示保存中／已保存／失败重试；资料编辑保留保存／取消。撤销设备、退出等危险动作独立放置并确认。失败和冲突保留草稿，不假装保存成功。
- 资料页仅在存在有效未提交修改时询问离开，选择保存失败后留页并保留输入；保存中返回不得重发或假装撤销已经发出的请求。自动保存偏好快速连续变化时，旧响应不覆盖新选择，最终服务端值必须与最新成功选择一致；失败必须保留可重试状态。
- 本地外观、服务端聊天偏好、每会话提醒、Android 系统通知权限分别表达。保留 Web 已有同类偏好的含义；系统拒绝权限不能显示“通知已启用”。

## 5. 美术与组件规格（VIS）

### 5.1 DL 身份与原生映射

- 默认以 DL“原色”的共享空间语义为视觉来源：中性表面、青蓝共享空间强调、清晰文字层级。铜橙属于相应品牌／通道语义，不为“更像 DL”而给 Workspace 增添 P2P 色彩或入口。
- 第一版完整交付一个默认主题的浅色／深色／跟随系统。主题家族与浅深模式为独立维度；其他主题家族可以后续适配，但不得提供无效选项或复制独立页面。不得宣称外观会跨端同步，除非已有对应服务端契约。
- 从主仓正式 token 建立可追踪映射，记录原值、RN 用途、平台差异及理由。补齐 `elevated/focus/success`、disabled、selected、pressed、destructive 等语义；页面禁止散落品牌十六进制值。
- 原生 elevation、阴影、模糊和透明度不照搬 CSS。默认不使用大面积玻璃、渐变、悬浮卡片堆叠、粗重描边或广告式标题。
- 人物头像为圆形，群／空间／工具用圆角方形，Bot 显式标识。自定义头像缺失或失败使用稳定占位，不以随机色／随机头像造成同一人在各页面身份不一致。

### 5.2 可执行的几何起点

以下为移动端设计起点，允许在真实设备评审后统一修订 token，不能每页自行改一组数字：

| 类别 | Android 目标 |
| --- | --- |
| 排版 | 系统字体与中文 fallback；消息正文 15–16sp、行高约 1.5；控件 14–16sp、辅助信息 ≥12sp，页面标题 20–24sp；紧凑聊天头部按控件尺度处理 |
| 间距 | 4/8/12/16/24/32dp；窄屏页面边距通常 16dp，气泡和工具区按内容密度使用 8/12dp |
| 圆角 | 按角色定义：常规控件 10–12dp、输入区约 16dp、Dialog／面板约 20dp；头像、标记与容器另有角色，不用一个圆角套所有元素 |
| 触控 | 主要与重复动作命中区 ≥48×48dp（高于既有 44dp 下限）；图标视觉尺寸可更小，点击热区不得与邻项冲突 |
| 消息宽度 | 普通气泡不铺满手机宽度，预留头像／状态与两侧留白；长文本、代码和表格采用各自受控布局，不能造成整页横向溢出 |
| 层次 | 背景、内容表面、弱表面、浮层四个明确层级；常规行不加阴影，状态不只靠颜色 |
| 系统栏 | 状态栏、导航手势区与键盘边界随当前主题可读；无双重安全区、内容遮挡或异常空白 |

### 5.3 必须交付的共享组件

至少覆盖 AppHeader、Avatar、ConversationRow、TopicRow、MessageRow／MessageContent、Composer、ReplyPreview、AttachmentPreview／FileRow、TransferItem、ObjectActionSheet、Button／IconButton、Input、Tabs／SegmentedControl、Switch／Select、SettingRow、InlineFeedback、EmptyState、Dialog 和更新提示。

所有组件提供适用的默认、按下、选中、禁用、加载、错误和读屏状态；退出／撤回等危险动作不能使用普通主按钮样式。短单选偏好使用内嵌分段控件，导航切换使用导航语义；不得拿一排按钮代替全部选择控件。使用现有 Lucide 图标，保持线宽和尺寸一致。

输入器外围保持轻量，只有输入本体承载语义底面、圆角和细边；不把整个底部区域染成大色块。动画表达状态而不拖慢操作，原生导航过渡按平台适配；减少动态时状态直接呈现。

建立仅开发构建可见的组件工作台，直接导入正式组件，使用合成数据展示长中文、长 URL、图片、文件、消息动作、错误、主题与大字体。不得维护一套只供截图的 Demo 组件；工作台通过不等于真实流程通过。

## 6. 聊天能力补齐与兼容（MSG）

本节以“同一内容在各端能理解、同一动作产生相同结果”为标准。支持对象不同可以隐藏不适用动作，但不能让私聊、群聊、Bot 和话题各自维护弱化的消息管线。

| 编号 | 改造要求 | 一致性与边界 |
| --- | --- | --- |
| MSG-01 | 统一渲染文字、换行、链接、@ 成员、系统／Bot 身份、附件、已知 emoji／自定义表情和当前已注册卡片 | 使用服务端结构化内容与 canonical 字段；不是一律显示 `plainText` 或原始 Markdown／表情标记 |
| MSG-02 | 富文本／Markdown 的安全子集、图片尺寸与加载失败、长内容折叠、代码／表格的可阅读呈现 | 与 Web 当前支持语义对齐；未知内容安全降级，禁止原始 HTML／脚本执行，不为展示加入任意 WebView |
| MSG-03 | 完整回复：选择消息→引用预览→取消／发送→点击引用定位 | 原消息不存在、被撤回、失权或不在当前窗口时有准确占位，不把摘要当原文；回复关系由原消息 ID 定义 |
| MSG-04 | @ 候选来自当前可见成员／Bot；支持纯提及发送、多个提及、删除和中文输入 | 发送结构化 `mention`，不能仅发送看似 @ 的字符串；Bot 触发与权限由服务端判定 |
| MSG-05 | 表情选择、已支持表情资源与合集、反应添加／取消、计数与本人选中态 | 共用 DL 资源标识与授权，保留原资产；不可把 reaction 当成一条聊天正文或伪造参与者 |
| MSG-06 | 菜单提供当前契约支持的复制、回复、反应、撤回、个人隐藏／恢复、常驻等对象动作 | 明确本人／他人／系统／撤回／话题关闭等能力；“仅自己隐藏”“撤回”“常驻”不得混成一个删除／置顶动作 |
| MSG-07 | 历史分页、引用／卡片定位、跳到最新、未读分界与阅读游标 | 游标来自服务端；只标记前台真实可见内容已读，读旧消息不自动清空尚未读的新消息；两端同步后结果一致 |
| MSG-08 | 草稿、发送中、失败、显式重试、重复回包与重连对账 | 重试复用逻辑消息 ID；成功一次只出现一条；前台切换／旋转／详情返回不丢未发送内容，不误发另一会话 |
| MSG-09 | 文件／图片选择预览、上传进度、取消／失败重试、成功附件、下载／系统分享 | 上传与发送分别反馈；响应丢失先查状态，不能重复收费或重复消息。下载校验大小和内容，退出清理临时私有副本 |
| MSG-10 | 话题发现、创建表单、加入／进入、退出、阅读、发送、回复、附件、提醒、群引用跳转 | 复用普通聊天组件和管线；所属群、加入状态、关闭状态和“同步到群聊”可见；默认话题内发送不能无意扩大受众；退出后同步参与状态，重新加入依服务端授权，不可保留参与者写入权限 |
| MSG-11 | 已注册话题／Bot 卡片的原生内容与允许动作；过期、失效与未知卡片降级 | 依据当前卡片 schema 与服务端授权，不执行未知 action；不能为已知日常卡片长期只保留“请到 Web 查看” |
| MSG-12 | 未读、提及、免打扰与通知一致；共享聊天偏好按账号加载／保存 | `all/mentions/muted` 的含义一致；本人、前台、重复与历史 replay 不触发错误通知；应用恢复后同步 canonical 状态 |

### 6.2 新能力与兼容边界

通用编辑、任意删除、转发、全文搜索不能仅凭旧协议示例添加。实现前逐动作核对当前 Go 路由、返回 capability、领域限制和契约测试；不存在的能力需另列服务端提案，不能由客户端伪造成功。本轮已明确要求的现有能力如发现原生鉴权或接口投影缺口，必须记录为阻塞依赖并配套后端修复，不能静默降级为“以后再做”。

未知 major／block／card 的 fallback 是兼容底线：保留安全摘要、作者和时间及准确升级提示，不渲染原始 JSON、不自动打开链接／下载／执行 Bot action。它不能掩盖当前已知消息类型未实现的问题。

## 7. 状态、可访问性与性能（QUALITY）

- 页面和对象都有初始加载、内容、空态、可恢复错误、离线／陈旧、无权／失效和终态；区分无消息、加载失败与看不到内容。错误贴近失败对象，不把所有错误塞到全局黄色横幅。
- 恢复网络后保留当前阅读／编辑状态，重放与受控 refetch 去重；失去成员权限立即撤销相应内容和操作，不残留可下载缓存入口。退出及账号切换隔离缓存、草稿、游标、通知与迟到响应。
- TalkBack 可读作者、正文、时间、发送状态和可用操作；动作面板、Dialog 有正确焦点与返回位置。字体放大至 200%、减少动画、浅深模式下都能完成任务；至少满足 WCAG AA 的文字／关键控件对比度要求。
- 320dp 窄屏、常见手机、横屏、平板、手势／三键导航和中文 IME 不出现遮挡、整页横向滚动或发送按钮不可达。视觉截图必须注明 dp、实际像素、fontScale、系统版本和主题。
- 消息流使用虚拟化和稳定 key；分页、图片异步尺寸与重连不能造成明显跳动。以 1,000 条合成混合消息验收分页、滚动、输入和内存，不以一次性装入所有历史掩盖分页问题。
- 在指定中端 Android 真机记录冷启动、进入缓存会话、首屏网络加载、键盘显示和发送反馈耗时，注明网络条件与测量方法；本地点击／发送中反馈目标在 100ms 内可见，网络完成耗时单独记录。不能拿桌面模拟器顺畅当作真机性能通过。

## 8. 实施顺序与交付物

| 阶段 | 交付范围 | 进入下一阶段的条件 |
| --- | --- | --- |
| R0 现状与设计确认 | 合成内容基线、能力／接口对照、手机流程、关键页浅深稿、token 映射、开放依赖 | 设计说明回答“用户在手机上如何完成任务”，不是只有一张好看的聊天截图 |
| R1 视觉基础与壳层 | 正式组件／工作台、导航、登录、列表、个人设置层级 | 所有根目的地、详情和关键状态使用同一设计语言；大字体与键盘主流程可用 |
| R2 聊天与内容 | 第 6 节全部核心能力、文件、话题、动作与状态，必要的服务端契约补齐 | 私聊／群聊／Bot／话题的适用能力矩阵闭合，无已知内容永久 fallback 或空动作 |
| R3 跨端与发布验收 | Web↔Android 双向场景、真机／无障碍／弱网、签名 release APK 与证据 | [验收账本](ACCEPTANCE.md) 的必过项全部有当前提交证据，剩余限制明确且不冒充完成 |

按阶段可提交小 PR，但不能将 R1 换肤包标为“DL 体验改造完成”。无需为纯视觉改造变更服务端 schema；新增原生依赖、协议或持久化格式按现有 ADR／发布要求另行说明。保留现有会话与默认域名配置；新 APK 的版本、签名、运行时和 OTA 兼容按发布规范处理，不能以重新安装清数据代替升级兼容验收。

最终交付包含：正式 RN 组件及页面、直接使用正式组件的工作台、与实现一致的架构／token 文档、逐项能力账本、合成数据截图和任务录像、功能与失败路径测试结果、可安装的签名包与明确限制。源码结构拆分只服务这些交付，不另起通用框架或全新后端。

## 9. 评审与完成判定

验收以真实用户任务为单位，分别记录 **规范已写、代码已实现、检查已运行、包已发布**，四者不可混用。每条证据带移动端和主仓提交、APK hash、服务端版本、设备及网络路径；未运行标为“未验证”，不以旧测试结果补齐新 UI 证据。

视觉评审要在实际 APK 上确认层次、密度、文字、颜色、状态和触控；跨端评审要在同一组被授权的合成会话中确认内容与动作。沿用已经批准的生产测试范围不意味着可以把真实消息或头像提交到公开仓库；默认使用隔离环境和合成数据。

验收操作步骤、证据栏和发布阻断条件统一维护在 [ACCEPTANCE.md](ACCEPTANCE.md)。仅“可登录、可发一条消息、可传一个文件”不得再作为本次完整验收结论。
