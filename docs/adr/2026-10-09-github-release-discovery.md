# GitHub 正式版本发现与服务兼容门禁

## 背景与行为

2026-10-09 实测服务端升级策略仍返回 0.1.0/code1 和旧测试包地址，GitHub 正式
Release 已为 0.2.3/code36。发布正式包后，旧的服务端 latest 配置不能自动通知用户。

客户端直接匿名读取固定 `timeStarry/duallane-mobile` 仓库的最新正式 Release。
「关于与更新」显示检查中、已检查、查询失败与可用版本；手动检查绕过本机节流。
启动和恢复连接时后台检查，不等待 GitHub 才登录或同步聊天。GitHub 失败不被解释
为「已是最新版」，也不解除服务端已确定的强制升级。

## 决定与边界

- GitHub 提供推荐新版、说明、APK 地址及 `build-provenance.json` 构建清单。
  草稿、预发布版、PR artifact 和更低版本不进入正式升级提醒。
- 服务端原有 release policy 保留最低版本与协议兼容性权威；其 latest 不再用于
  推荐升级。强更入口优先使用满足门槛的 GitHub 正式包，否则保留服务端维护者入口。
- 版本和 Android 构建号都不能降低，且至少一项提高，才能建议安装；同版本更高
  构建可更新，较高候选包不会被推荐降级。
- GitHub 请求不用 Workspace API client，不携带会话 token、用户、空间、消息或
  本机版本参数。外部 JSON、仓库路径、版本、包名、APK 名称／大小／摘要均需校验。
- 只缓存公开版本元数据和检查时间，自动检查最多每 15 分钟一次；退出、服务切换
  或 Runtime 销毁时取消请求，迟到结果不写入新上下文。
- 下载仍打开系统浏览器，由 Android 安装器确认安装和校验签名。此改动不自动安装，
  不声称已经下载并验签 APK；不新增原生模块、权限、OTA、服务端 API 或数据迁移。
- 发布流水线为 APK/AAB 生成构建清单与 SHA256SUMS；正式 Release 先以草稿上传完整
  附件，再公开为 latest。手动候选构建只产出 artifact。

## 验证与回滚

回归覆盖正常／不存在的正式版、外部 JSON 与 URL 篡改、降级、并发检查、节流、
超时、响应正文挂起、销毁／账号切换和服务端强更优先级；发布脚本使用合成包与
受控 inspection fixture 校验清单。另运行移动端完整检查和 Android 打包检查。
网络和真机检查记录实际结果，不把测试夹具当作发布流水线或安装通过。

回滚客户端与发布脚本即可，无 Workspace 数据回滚。旧客户端仍使用服务端原有
兼容接口；现有 0.2.3 附件清单无需修改。
