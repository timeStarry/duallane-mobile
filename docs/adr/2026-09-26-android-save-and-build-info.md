# ADR 2026-09-26：Android 文档保存与安装包版本读取

## 背景

聊天附件的「下载并保存」原先调用系统分享页；用户选不到明确的保存目标，分享文件名还带有应用缓存的随机前缀。关于页从 Expo 常量读取版本，在已安装 `0.2.0` 包上显示为 `0.1.0`。两者都需要以当前安装包和 Android 文档提供方为准。

## 选项与决定

- 继续借用分享页：无法确认文件已写入用户选中的位置，也不能把分享完成当成保存成功。
- 请求广泛存储权限并写入 Downloads：不适合 Android 版本差异，也扩大文件访问范围。
- 使用 Android `ACTION_CREATE_DOCUMENT`：采用此方案。用户选择目标和名称后，原生模块只读取应用缓存中的已授权下载文件，通过返回的文档 URI 复制字节；取消返回未保存，复制失败清理新建文档并报告错误。分享仍走独立动作。

同一 `ReactPackage` 暴露 `BuildConfig.VERSION_NAME` 与 `VERSION_CODE`，关于页优先显示安装包实际版本。JS 侧保留 Expo 常量作为其他环境回退，不为读取版本引入新依赖。新增原生代码需要重新构建 APK；模块不持有服务端令牌，不改变下载授权、配额或消息存储。

## 迁移与观测

接口仅供 Android 使用；现有缓存无需迁移。手动验证系统文档选择器保存、取消、重复文件名、字节哈希和分享名称；检查关于页与 PackageManager 一致。CI 构建测试签名包并安装启动，单测覆盖 JS 的保存／分享分流和版本选择。

## 回滚

回退 `SaveFilePackage` 注册与 JS 调用并重新打包；已由用户保存到外部文档提供方的文件保持原样，不由应用删除。
