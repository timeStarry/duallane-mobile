# 移动端安全与数据规范

## 信任边界

移动端只访问 Workspace server-retained lane。后端负责登录、membership、权限、配额、
保留、审计和通知收件人；客户端隐藏按钮不构成授权。P2P 内容、`#k=`、WebRTC 和 ntfy
topic 不进入移动端存储、日志、遥测或通知。

## 凭证与缓存

- GitHub 使用 PKCE + 系统 Custom Tabs；不使用 WebView 收集密码。
- access token 只放内存；refresh token 放 Android Keystore，轮换、重放检测、退出撤销并删除。
- SQLite/KV 只存可丢失的会话、最近消息、草稿和游标；退出登录清理账号隔离数据。
- 深链和通知只带不可授权的资源引用，打开后重新做服务端授权。

搜索历史仅保存主动提交／打开结果的关键词，按账号、服务和空间隔离，最多 12 条；
支持单条删除及清空，退出登录随本账号缓存清理。关键词不发送到服务端、不写日志。
搜索结果只引用当前可读的会话和话题，不能使缓存对象绕过读取权限。

聊天图片快捷发送只使用系统选择器授予的选定图片，禁止申请整个媒体库、相机或
麦克风权限。系统确认后仅向选择时绑定的已授权目标发送，不消费文字／回复／文件草稿。
选图取消及账号／目标失效不发送；应用副本与上传失败任务沿用账号隔离及清理规则。
权限、可用附件和传输配额仍由服务端校验，不能因为选择器已确认就跳过预留。

头像选择仅接受 JPEG、PNG、WebP 的非空图片，上限 5 MiB；超限应在读取字节和发请求前
拒绝。选择只创建预览，原生解码成功且明确确认后才发送 raw image；服务端继续执行本人授权、图片
方向校正及中心裁剪。系统选择器的应用缓存副本在取消、失败、离页和退出时清理，
不得删除用户源文件。账号、API、epoch、页面及请求代次失效后，不应用迟到结果；
头像图片、URI 和文件名不进入日志。
成功选择的预览副本进入头像专属目录，选择器副本随即清理。进程重启后不能只依赖
旧的内存 Map 来清理，需清掉无活跃归属的旧头像副本；同进程的当前选择应保留。

## 日志、通知和内容

日志只记录匿名诊断、错误 code、route 族、HTTP status、耗时和版本；不记录 token、消息正文、文件名、
邀请链接、URL query、对象 key、完整 URL 或实时 seq。传输失败会把诊断 code 附在用户可见文案后，
便于对照 logcat。本地通知默认只显示“有新消息”，遵守会话
`all/mentions/muted` 偏好；通知点击不绕过登录、成员或文件授权。未知消息不执行 HTML、脚本、
远程组件、自动下载或 Bot action。
